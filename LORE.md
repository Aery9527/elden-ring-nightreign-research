# LORE

## Overview

- Knowledge about the game `ELDEN RING NIGHTREIGN`, and research records of specific values that the game does not state.

## Project Ground Rules

- AI agent documents MUST stay bilingual with equivalent content (the file without a suffix is the English version), for example SKILL.md = SKILL_ch.md, AGENTS.md = AGENTS_ch.md, and so on.
- Links in AI agent documents MUST match the document's language: an English file links to the English target, and a Traditional Chinese file links to the _ch target when one exists.
- The site is published with Netlify. [netlify.toml](netlify.toml) publishes the `public/` directory with no build command:
  - All site files (HTML, CSS, images) go under `public/`; files outside `public/` do not appear on the site.
  - Pages link to each other with relative paths to `.html` files and do not rely on Netlify pretty URLs.
  - Pages load game data with `fetch`, so preview them locally through an HTTP server (for example `python -m http.server -d public`); a page opened directly as a local file (`file://`) cannot load the data.
  - When adding a topic page, also add a row to its topic's table on the home page [public/index.html](public/index.html); a new topic gets its own `h2` chapter there.
  - When a page is renamed or merged into another page, add a 301 redirect from the old path in [netlify.toml](netlify.toml) and keep the old heading ids so old anchors still work. When a published section moves to another page, map its "page#id" to the new page in the old-anchor table (`moved`) of [public/nav.js](public/nav.js); when a section is removed or merged within the same page, keep its old id on the element that takes over its content.
  - Every page loads [public/nav.js](public/nav.js) before [public/render.js](public/render.js), so the header exists before rendered content scrolls to the URL anchor, and uses the same sticky `<header class="site-header">` markup as the existing pages. The header is the site-wide navigation: from any chapter the reader can see every chapter of the page and jump to it without returning to the top, so pages MUST NOT keep a hand-written table of contents. The script builds both header rows from the page itself:
    - Breadcrumb row: the site home, the page `h1` (omitted on the home page, where the home link already names the page), and the `h3` the reader is currently in, each linking to the top of that level. On narrow screens the row wraps instead of scrolling horizontally.
    - Chapter row: every `h2` of the page in document order, named by its rendered text, with the current chapter marked by `aria-current="location"` and no chapter marked in the introduction before the first `h2`. On wide screens the row wraps so every chapter stays visible. At 640px and narrower, or 500px and shorter (a phone held sideways), the row becomes a button that names the current chapter (章節：<chapter>, or 本頁章節 in the introduction); the button opens the chapters as a vertical menu below the header and over the content, which scrolls inside itself when it is too long and opens with the current chapter in view. Choosing a chapter, pressing Escape, or clicking outside the menu closes it.
    - Each page divides its content into `h2` chapters, so the chapter row lists the page's major sections. Only `h2` and `h3` headings with an `id` appear in the header, so every section heading MUST have an `id`. The chapter row is built from the `h2` headings in the HTML; `h3` headings are collected again whenever the content changes, so those that render.js adds also appear in the breadcrumb.
  - Every source the site cites is listed once in the "資料來源" chapter (`#sources`) of the home page [public/index.html](public/index.html); topic pages MUST NOT have their own sources section, and relic tables MUST NOT have a source column. When a page starts citing a new source, add or update its row in that table. Inline citation links in body text and the source names shown for conflicting candidates stay on the pages.

## Game Data Rules

- The site reads game values (numbers and rule tags), the effect, stat, and category names that the placeholders render, and their sources only from `public/data/`; maintenance inputs that produce part of these files live in `tools/` (see Relic Data Generation):
  - [public/data/common.json](public/data/common.json): game version, stats (`stats`), icons, characters, tags (`tags`), skill groups (`skillGroups`), interface text (`labels`), and sources shared by all pages.
  - `public/data/relics/<category>.json`: one file per top category of the in-game relic filter (`general`, `character`, `armament`, `demerit`), holding that category, its subcategories, and its effects.
  - `public/data/armaments/weapons.json` and `public/data/armaments/spells.json`: weapons and spells keyed by their in-game ID (the `EquipParamWeapon` row, or the spell ID a weapon slot references), each with `name` (`zh` and `en`, or `null` when no source names it), `icon`, `tags`, and sources. A weapon also keeps its `sortId` and, when it carries spells, `spells` mapping each slot (`R1`, `R2`) to a spell ID. A named weapon also keeps raw param values (see Armament Data Generation): `attack` (`physical`, `magic`, `fire`, `lightning`, `holy`), `scaling` (keyed by the `stats` keys `strength`, `dexterity`, `intelligence`, `faith`, `arcane`), `critical`, `passive` (`zh` and `en`, or `null`), `buildup` (ailment key to value, `{}` when none), and `skill`: `default` (the param default skill ID) and `pool` (the generation pool candidate skill IDs, `[]` when none). A spell with a `Magic` row also keeps raw cost params: `cost` (`fp`, `stamina`) and `chargeCost` (`fp`, `stamina`, or `null`). Every weapon row stays its own item even when it shares a `sortId` with another row; an unnamed row is never given another row's name.
  - `public/data/armaments/skills.json`: skills keyed by `SwordArtsParam` ID, each with `name` (`zh` and `en`), `textId`, `icon`, `group` (a `skillGroups` key), `fp` (`L1`, `L2`, `R1`, `R2`), `caption` (`zh` and `en`), and sources. Skills that share a `textId` stay separate items and keep their own `fp` and `icon`.
  - `public/data/characters/nightfarers.json`: Nightfarers keyed by the `characters` keys of common.json, each with `heroId` (the `HeroParam` ID), `grades` (keyed by the `stats` keys `maxHp`, `maxFp`, `maxStamina`, `strength`, `dexterity`, `intelligence`, `faith`, `arcane`, each `S` to `D`), `anchorLevels` (the levels that have a `HeroStatusParam` row), `levels` (`1` to `15`, each with the eight base stats and `maxHp`, `maxFp`, `maxStamina`), `passive`, `skill`, and `art` (each with `name`, `summary`, and `description` in `zh` and `en`, `icon`, and `effects`: a list of `{ zh, sources, note? }`, where `note` is `{ zh, sources }`; `skill` also has `cooldown` in seconds, `0` meaning none, and an optional `cooldownNote` of the same shape as `note`), and sources (see Character Data Generation). Character names and icons stay in `characters` of common.json.
  - Data for another game topic goes in its own file or directory under `public/data/` named after the topic and split by the game's own grouping, as `relics/` follows the in-game relic filter; definitions shared by several topics stay in `common.json`.
  - Each page lists the files it loads in `<body data-load>`, for example `common relics/general`. [public/render.js](public/render.js) tells a relic category file (`category`), a weapon file (`weapons`), a spell file (`spells`), a skill file (`skills`), and a character file (`nightfarers`) apart and stops with an error on any other file; it stops on a duplicate effect key, effect or tier `gameId`, subcategory key, weapon ID, spell ID, or skill ID (each kind checked on its own), on an item tag or effect `targets` key not defined in `tags` (except the ID lists `spell` and `skill` of `targets`), on an effect `stats` key or a stat `base` not defined in `stats`, when spells are loaded, on a carried spell or a `targets.spell` ID that is missing, and, when skills are loaded, on a named weapon without `skill.default` and `skill.pool`, or a skill ID of a weapon or of `targets.skill` that is missing; and, when the character file is loaded, on characters that differ from `characters` of common.json; it MUST NOT let a later file override an earlier one.
- HTML holds `data-*` placeholders that [public/render.js](public/render.js) fills in; game values, including those in body-text examples, MUST NOT be hard-coded in HTML. Body prose (for example character names) and selection keys in `data-*` attributes (for example tier or level numbers) may stay in HTML. `<span data-character="<character>:<level>:<stat>">` shows a level value of the character file, so a page that uses it loads `characters/nightfarers`.
- Value states:
  - A plain value is what the effect's `sources` report.
  - `null` means unverified; it MUST NOT be treated as 0 or false.
  - `{ "conflict": [{ "value": ..., "sources": [...] }] }` means the sources disagree; keep every candidate and never default to one.
  - These states apply to every field, including rule fields such as `stacking.stacks`; a calculation runs only when every rule it needs is explicitly satisfied, and otherwise shows the blocking state.
  - `sourcesFor` maps a field path (for example `stacking.combine`) to its sources and replaces the effect's `sources` for that field.
- Store percentages as signed numbers (for example `10`, `-5`); code derives multipliers.
- An effect with +1/+2/+3 tiers is one effect with a `tiers` array; each tier keeps its in-game `gameId`. A tier without a `+N` suffix in its name is `tier: 0`. A rule field that differs between tiers is stored on each tier instead of on the effect.
- Record each effect's resource change as the source states it; do not derive it from a universal per-point conversion.
- Tags classify game items so relic effects can be matched against them. Their definitions live in `tags` of [public/data/common.json](public/data/common.json), grouped by dimension (`weaponType`, `spellType`, `spellSchool`); each tag is `{ "name": { "zh", "en" }, "param": <value> }`, where `param` is the game param value the tag stands for (`EquipParamWeapon.wepType`, `Magic.ezStateBehaviorType`, `Magic.subCategory1`/`subCategory2`). Weapon type names are the in-game relic filter subcategory names; spell type and school names are excerpts of in-game relic effect names (for example 卡利亞劍 from 強化卡利亞劍的魔法). A spell school is defined only when a relic effect targets it.
  - An item stores `tags` as `{ <dimension>: [...] }`: a list of tag keys, where an empty list means checked with no defined tag; `null` means unverified; a `conflict` keeps every candidate.
  - A relic effect's `targets` uses the same dimensions, for example `{ "spellType": ["sorcery"], "spellSchool": ["carian-sword"] }`, plus `spell` and `skill`, lists of spell IDs and skill IDs that name individual spells and skills; a spell is matched against `spell` and a skill against `skill` by its own ID, so neither is defined in `tags` or stored in an item's `tags`. An item matches when, for every dimension in `targets`, its tags share at least one key (AND across dimensions, OR within one); a dimension the effect does not list is not checked. A known mismatch in any listed dimension is a mismatch; otherwise an unverified listed dimension makes the match unverified, and a conflicting one shows the conflict.
  - `targets` records the item categories or items that a game param field or a verified reference chain of the effect names (see Relic Data Generation). A match only means that param relation exists; how the effect works, when it triggers, and its limits are stated by the effect itself. An effect without `targets` is not modeled, which is not the same as being unrelated.
- A relic effect's `stats` lists, in `stats` order, the keys of `stats` in [public/data/common.json](public/data/common.json) whose value a game param field of the effect changes (see Relic Data Generation). Each stat's `param` maps a param table (`SpEffectParam`, `HeroStatusParam`) to a non-empty list of the fields that change it, and a change in any one of them counts; `poise` maps to `toughnessDamageCutRate`, the rate of poise damage taken. `attackPower` groups the five attack rates (`physicsAttackRate`, `magicAttackRate`, `fireAttackRate`, `thunderAttackRate`, `darkAttackRate`), `damageNegation` the eight damage cut rates (`slash`, `blow`, `thrust`, `neutral`, `magic`, `fire`, `thunder`, `dark` + `DamageCutRate`), and `ailmentResistance` the seven resist points (`change` + `Poison`, `Disease`, `Blood`, `Freeze`, `Sleep`, `Madness`, `Curse` + `ResistPoint`). A cap stat (`maxHp`, `maxFp`, `maxStamina`) has `base`, the base stat that also changes it (`vigor`, `mind`, `endurance`). As with `targets`, a match only means the param relation exists, an effect without `stats` is not modeled, and `stats` is a rule field. `stats` comes only from the game params, so it has no unverified or conflicting state: [public/render.js](public/render.js) stops with an error when it is not a list.
- Relic effects follow the in-game relic filter tree: every effect has a `subcategory`, and each category and subcategory keeps its in-game param `gameId`. A category Chinese name not taken from game text is a site translation, and pages MUST say so.
- Every effect has `name` (`zh` and `en`) and `icon`. `icon: null` means no in-game image that meets the image rules exists; it MUST NOT be replaced with a different image.
- The weapons page (`weapons.html`), the sorceries page (`sorceries.html`), and the incantations page (`incantations.html`) render their chapter names, chapter effects, and rows from data; the HTML holds only the chapter skeleton, and names and rows MUST NOT be hand-written:
  - Weapons page: one `<section data-weapon-type="<type>">` per `weaponType` tag, with the `h2` id `weapon-type-<type>`; the page stops with an error unless every tag has exactly one chapter. The chapter table lists the named weapons of that type by `sortId` with the columns 基礎攻擊 and 能力補正 (one line per non-zero value, named by the attack labels and the stat names) and 特殊效果 (致命補正 <value> when `critical` is not 1, the value of most weapons; then the `passive` name; then 命中累積<ailment> <value> per `buildup` entry), and 戰技: when `skill.pool` holds only `skill.default`, the cell shows that skill alone; otherwise it shows 參數預設：<skill>, then, when `pool` is not empty, the 生成池候選 list. Each skill shows its icon and name and links to `skills.html#skill-<id>`. A list with one item shows as 生成池候選：<skill>; a list with two or more items is a collapsed `<details>` whose summary gives the count, for example 生成池候選 44 種. The count covers only `pool`, which may not hold the default skill. The page loads `armaments/skills` and stops with an error without it. An empty cell shows —, which only means the stored fields have nothing, not that the weapon has no other effect. These values come only from the game params, so they have no unverified or conflicting state: a missing or extra key, or a value that is not a number, stops the page. The page states that the values are raw params, not in-game displayed values. Each row has the id `weapon-<id>`, the target of the 相關武器、法術與戰技 links on the relic pages. The `h1` keeps the id `weapons`, and the `#limitations` chapter holds `<tbody data-unlisted-spells>`: every referenced spell whose type is unverified or conflicting, with its type, school, carriers, and 相關遺物詞條 column.   - Sorceries and incantations pages: `<section data-spell-type="<type>">` is the type chapter (`h2` id `sorceries` or `incantations`), listing only the effects whose `targets` match the type alone. Each `<section data-spell-type="<type>" data-spell-school="<school>">` is a school chapter (`h2` id `spell-school-<school>`); an empty school is the 無已定義系別 chapter (`h2` id `<type>-no-school`).   - Related effects are matched by the rules above and shown in layers, so an effect appears only at the highest layer that matches: the type chapter, then the school chapter (effects that also match the type alone are omitted), then the spell row, below the spell name (effects that also match the school chapter are omitted, which leaves `spell` targets). It is computed on the page, which loads all four relic category files and both armament files, and no reverse list is stored in the data. A match only means the param relation exists, not that the effect applies to every item of the chapter. The 搭載法器 column lists named carriers with the slots (`R1`, `R2`) that hold the spell, and unnamed carriers only as a count of distinct weapon IDs per slot. `targets` stored on tiers is not rendered yet: the page stops with an error instead of merging tier results.
  - `armaments.html`, the former combined page, redirects to `weapons.html` in [netlify.toml](netlify.toml); the browser keeps the anchor. On the weapons page, [public/nav.js](public/nav.js) moves `#sorceries` and `#incantations` to the new pages, and [public/render.js](public/render.js) moves a `#spell-<id>` the page does not hold to the page of that spell's type, so old anchors still work. - On the attributes page, the 相關遺物詞條 column of each stat row (`<td data-stat-effects="<stat>">`) lists the relic effects whose `stats` hold that stat, each linked to its effect row; a cap row then lists, under 經由<base stat name>, the effects whose `stats` hold its `base` but not the cap. - Effect rows of a relic table are rendered from data with `<tbody data-relic-table="<subcategory>">`; effect rows MUST NOT be hand-written in HTML. In the effect column the detail comes first, followed by the rule line; the value line built from structured values (`modifier`) appears only for an effect without a detail, because the detail already states the same numbers. Conflicting candidate values are always listed with their sources. An effect with neither a detail nor structured values shows 未載明數值 in its tone. The rule line omits availability, which the 種類 column shows, and the self-stacking of a buff, which its tone shows; blue also means multiple copies add, so a buff's combine rule is listed only when it is not `add`, and its across-tier rule only when it is not `true`; conflicting self-stacking is still listed with its candidates. Demerit effects are always red, so their rule line keeps the self-stacking state. The 種類 column shows 一般 and/or 深層 from `availability`, or the icon and name of each relic for a fixed-relic effect (`relics`); when a tiered effect appears in more than one kind, every line lists the tiers of that kind (for example 一般：+1、+2、+3 and 深層：+3), and a tiered effect in a single kind shows only the kind (for example 一般); unverified or conflicting availability shows its status. Unverified or conflicting matches and unnamed items are not listed, and the line is omitted when nothing is listed. A value that is not a list, or `targets` stored on a tier, stops the page with an error. - [public/render.js](public/render.js) colors data-generated detail lines, value lines, and body-text examples by tone: effects in the demerit category are red (`tone-debuff`); other effects are blue when they stack with themselves (`stacks: true`, `tone-stack`) and green when they do not (`stacks: false`, `tone-solo`); unverified or conflicting stacking keeps the default color in bold (`tone-unverified`). In relic tables, every rule label whose state is unverified or conflicting, and the 來源分歧 label of conflicting candidate values, is also bold (`tone-unverified`). A rule-line equivalent value (for example "equals Vigor +5") takes the effect's tone. Penalty phrases listed for a detail are red inside its tone. The rule label stating that a curse effect is required (`requiresCurse: true`) is red. Each relic page shows a color legend fixed to the bottom of the viewport (`<aside class="tone-legend" data-legend>`), rendered from `legend` in [public/data/common.json](public/data/common.json): each item has a `tone` (the class suffix), a `label`, and a `tip` shown on hover or focus; the items are 不可疊加 (green), 可疊加 (blue), 負面 (red), and 未核實 (bold). Tone classes MUST NOT be set by hand in HTML.
- When every tier detail of an effect ends with the same parenthetical note (for example （不適用於隱士、復仇者、執行者）), the page removes the note from each tier line and shows it once after them as 各等級：<note>; the data keeps the full text.
- `detail` holds the community detail text of an effect or tier: `en` is the source text verbatim and `zh` its translation. A detail whose number, item, or location contradicts the pinned game params is instead rewritten from the params in both languages and carries its own `sources`. An effect the dataset gives no detail gets one written from the params only when an explicit reference chain from its AttachEffectParam row gives the numbers and the detail tells the reader more than the name; otherwise it has no detail.

## Relic Data Generation

- `public/data/relics/*.json` are generated by [tools/import-relics.mjs](tools/import-relics.mjs) (`node tools/import-relics.mjs [category ...]`, run from the repo root); they MUST NOT be edited by hand. Edit the inputs and rerun:
  - [tools/relics-config.json](tools/relics-config.json): the pinned commit of each source, the category tree, the nightfarer columns, the status icon ID → icon key map (`null` = no matching licensed image), and the relic icon ID → icon key map.
  - [tools/relics-curated.json](tools/relics-curated.json): hand-curated effects matched to generated effects by `gameId`; their fields override generated values, and the script prints every overridden difference.
  - [tools/relic-details-zh.json](tools/relic-details-zh.json): the Traditional Chinese translation of each community detail, keyed by `gameId` and stored with its English original.
  - [tools/relic-stacking.json](tools/relic-stacking.json): self-stacking values for tiers the dataset leaves unknown, keyed by `gameId`, taken only from a community source that states them explicitly (the community sheet or Fextralife); each entry stores `stacks` (a boolean, or a `conflict` when the sources disagree), `sources`, and the quoted source rows in `quotes`. The script fills only unknown values and lists the sources in the effect's `sourcesFor["stacking.stacks"]`, together with the source of any tier the dataset already gives.
  - [tools/relic-details-params.json](tools/relic-details-params.json): details written from the game params, keyed by `gameId`; each entry stores the community `source` text (`null` when the dataset has no detail), the rewrite in `en` and `zh`, the param evidence in `params`, and optional `sources` (default `game-params`). A `gameId` MUST NOT appear in both detail files.
  - [tools/relic-penalties.json](tools/relic-penalties.json): penalty phrases inside the Traditional Chinese detail of a buff effect, keyed by the `gameId` that owns the detail; each value is an array of exact substrings (for example `"生命力 -5"`), written to `detail.penalties`. List every penalty in a detail, including each level's number.
- The script stops without writing when a curated effect, translation, effect or relic icon, character, or source reference (`sources`, `sourcesFor`, conflict candidates) has no match; when two curated effects map to the same `gameId`s; when a source field has an unknown enum value; when the English original of a translation or the `source` of a param rewrite differs from the source; when a `gameId` has both a translation and a param rewrite; when a param rewrite lacks `en`, `zh`, or `params`, has an empty `sources`, or has no matching effect; when an effect stores a rule field (`availability`, `requiresCurse`, `stacking`, `targets`, `stats`) both on the effect and on a tier; when an effect yields more than one different `targets` condition set, a `startMagicId` that no weapon slot references, or a `startSwordArtsId` that is not a skill in `public/data/armaments/skills.json`; when a stacking entry has no matching effect, targets a tier the dataset already gives, cites a source other than the community sheet or Fextralife, lacks one quote per source, or has an invalid `stacks` (a conflict needs at least two boolean candidates with different values, each citing listed sources); when a penalty entry is not a non-empty array of non-empty strings, has no matching detail, lists a phrase missing from the detail, or lists a phrase ending in a digit that matches only part of a longer number not covered by a longer listed phrase; or when either detail file, the stacking file, or the penalty file repeats a key or differs from its canonical `JSON.stringify` output with 2-space indentation. Fix the input instead of bypassing the check.
- The script generates `targets` from the SpEffectParam rows referenced by each effect's `passiveSpEffectId_1`–`_3`, together with the rows those reference through `analyzeSelfLevel1_effectId`–`3_effectId`: `triggerOnWepType`, `wepTypeTrigger` when `wepTypeTriggerCount` is above 0 (an equipped-count condition), and `weaponTypeDiscovery` give a `weaponType`; a `magicSubCategoryChange1` that is a defined school, with exactly one of `magParamChange` (sorcery) and `miracleParamChange` (incantation) set, gives a `spellType` and a `spellSchool`; exactly one of those flags with all three `magicSubCategoryChange` fields 0 and no weapon type gives a `spellType`; a `magicConsumptionRate` or `miracleConsumptionRate` other than 1 gives `sorcery` or `incantation`; a `startMagicId` gives `spell`, which MUST be a spell some weapon slot references; a `startSwordArtsId` gives `skill`, which MUST be a skill in `public/data/armaments/skills.json`, so run `node tools/import-armaments.mjs` before this script; the script skips the values -1 and 0 (the `SwordArtsParam` row 0 has no name or caption). Only param values defined in `tags` produce a tag, and an effect with no such tag and no `spell` or `skill` ID gets no `targets`. Identical conditions found more than once are kept once. `targets` is a rule field: it is stored on the effect when every tier has the same value, otherwise on each tier, and its source is recorded as `sourcesFor.targets: ["game-params"]`. The script stops when an effect yields more than one different condition set.
- The script generates `stats` from the SpEffectParam rows reached from each effect's `passiveSpEffectId_1`–`_3` and `permanentSpEffectId` through `replaceSpEffectId`, `cycleOccurrenceSpEffectId`, `atkOccurrenceSpEffectId`, `accumuOverFireId`, `accumuUnderFireId`, and `analyzeSelfLevel1_effectId`–`3_effectId`. A stat is changed when one of its `SpEffectParam` fields in a reached row differs from the neutral value (1 for a mapped field ending in `Rate`, otherwise 0), or when its `HeroStatusParam` field is not 0 in any of the rows X, X+1, … that follow without a gap from a reached row's `heroStatusModifier` X (the level points of a character effect). Effects that change no stat get no `stats`. The script stops without writing when a `param` value is not a non-empty list, a mapped field is not in the param table header, or a mapped field value in a reached row is not a number. `stats` is stored on the effect when every tier has the same value, otherwise on each tier, and its source is recorded as `sourcesFor.stats: ["game-params"]`.
- To update a source, change its commit in the config, rerun the script, and review the printed differences and the changed translations before committing. After a game param update, check every param rewrite against the new params.
- Translating a detail:
  - Every number keeps identical digits; never compute, round, or convert units.
  - Use the effect's official Chinese name and game terms; a term with no official Chinese name stays in English.
  - Translate source notes such as `TODO` as `（原文註記：……）`; where the source contradicts the effect name, translate literally and add `（原文如此）`. MUST NOT correct the source in a translation; a contradiction with the game params goes to the param rewrite file instead.

## Armament Data Generation

- `public/data/armaments/*.json` are generated by [tools/import-armaments.mjs](tools/import-armaments.mjs) (`node tools/import-armaments.mjs`, run from the repo root); they MUST NOT be edited by hand. Both import scripts read the pinned sources of [tools/relics-config.json](tools/relics-config.json) through [tools/sources.mjs](tools/sources.mjs), so relics, weapons, spells, and skills always come from the same game params.
  - Weapons: every `EquipParamWeapon` row whose ID is a multiple of 10000, whose `wepType` has a `weaponType` tag, that has a name, whose `sortId` is not 9999999, and that an `EquipParamCustomWeapon` row targets (`targetWeaponId`, Nightreign's weapon generation param with weapon level and passive tables); plus every row that carries a spell (`equippedSpell_R1`/`equippedSpell_R2`), named or not. Base-game weapons absent from Nightreign, such as Dryleaf Arts and Dane's Footwork, keep `EquipParamWeapon` rows but have no `EquipParamCustomWeapon` row, so a name and a type alone do not show that a weapon is in the game.
  - Spells: every ID a weapon spell slot references. `spellType` comes from `Magic.ezStateBehaviorType`, and `spellSchool` from `Magic.subCategory1`/`subCategory2`, keeping only values with a defined tag (`[]` when none). A referenced ID with no `Magic` row gets `null` for both and is never classified from its name, its carrier, or the base-game list it appears in.
  - Names: the game params carry no names and no Nightreign text for weapons or spells is available, so names come from Elden Ring base-game text pinned as `erText` (soarqin/ERTools): weapons from `WeaponName` by weapon ID; spells only from the base-game sorcery and incantation lists by ID, never from `GoodsName`, whose IDs collide with key items. Blank, `%null%`, and `[ERROR]` entries are not names. An item without a name in both languages has `name: null`. Names record `sourcesFor.name: ["er-base-text"]`, and pages MUST say they are base-game reference names not confirmed for Nightreign.
  - Weapon values, only for named weapons: `attack` from `attackBasePhysics`, `attackBaseMagic`, `attackBaseFire`, `attackBaseThunder`, `attackBaseDark`; `scaling` from `correctStrength`, `correctAgility`, `correctMagic`, `correctFaith`, `correctLuck`; `critical` from `criticalAtkRate` (not `throwAtkRate`). They are raw params: Nightreign attack power also changes with level and rarity, and that calculation is not verified, so they MUST NOT be presented as in-game attack power or scaling grades. `passive` is the name of the `AttachEffectParam` row that `attachEffectId` references, looked up by its `attachTextId` in the Nightreign effect text (`game-text`); only the name is stored, and the values and conditions of its effects (through `passiveSpEffectId_1`–`3`, `onHitSpEffect`, and `permanentSpEffectId`) are not stored yet. `buildup` takes only the ailment buildup fields (`poizonAttackPower`, `diseaseAttackPower`, `bloodAttackPower`, `freezeAttackPower`, `sleepAttackPower`, `madnessAttackPower`, `curseAttackPower` as `poison`, `rot`, `blood`, `frost`, `sleep`, `madness`, `deathBlight`) of the `SpEffectParam` rows that `spEffectBehaviorId0`–`2` reference, skipping zero; other fields of those rows are not stored. Shield guard rates and `heroID` are not stored.
  - Weapon skills, only for named weapons: `skill.default` is `swordArtsParamId`. `skill.pool` is the union, sorted by ID, of the skills with a `chanceWeight` above 0 in the `SwordArtsTableParam` pools that the weapon's `EquipParamCustomWeapon` rows reference through `swordArtsTableId`. A generation row with `swordArtsTableId` -1 has no pool; the params do not show which skill such a weapon gets, so the default skill is not assumed for it and is not added to `pool`. The default skill may be missing from `pool`. These are param relations, not proof of what a picked-up weapon has or how likely each skill is, so pages call the default the "param default" and MUST NOT present it as the weapon's fixed skill.
  - Skills: every `SwordArtsParam` row that a named weapon's `skill.default` or `skill.pool` references. `name.en` and `caption.en` come from the base-game `ArtsName` and `ArtsCaption` by `textId`, pinned as `erArts` (EldenRingTextExplorer); `name.zh` comes from the base-game Ash of War names in `erText` (`ashesofwar`): the Ash of War whose English name, without the `Ash of War: ` prefix, equals the skill's English name gives its Traditional Chinese name without the `戰灰：` prefix. Ash of War IDs are usually 100 times the skill ID but not always (Ash of War 30900 is skill 10, and 31000 is skill 309), so IDs MUST NOT be used to match them. A skill with no such Ash of War, such as a weapon's unique skill, takes `name.zh` from the site conversion below; its Traditional Chinese name MUST NOT be translated from English or invented. `caption.zh` is always the site conversion. The conversions live in [tools/skill-text-zh.json](tools/skill-text-zh.json), keyed by `textId`: `cn` keeps the official Simplified Chinese `name` and `caption` of the base game exactly as in the `erArtsCn` source (heroboy/EldenRingMapTranslate, a community copy of the game text), and `zh` holds the site's Traditional Chinese conversion. Conversion rules: phrases are first replaced by the official Nightreign Traditional Chinese wording (for example 血量 → ＨＰ, 专注值 → ＦＰ, 通过 → 透過); every other character takes its Traditional form chosen by context (for example 回旋 → 迴旋, while 精通 stays 精通, and 红发 → 紅髮); punctuation follows the official Traditional Chinese text (“” → 「」, · → ‧); nothing is added or removed, and digits and line breaks stay. The official Nightreign Simplified and Traditional Chinese texts are only a reference for these choices, not proof that the official Traditional Chinese equals such a conversion, so pages call the result a site conversion. When an Ash of War name exists, `zh.name` MUST equal it, which checks the conversion. Names record `sourcesFor` `name.en: ["er-arts-text"]` and `name.zh` as `["er-base-text"]` (Ash of War) or `["er-arts-cn-text"]` (conversion); captions record `caption.en: ["er-arts-text"]` and `caption.zh: ["er-arts-cn-text"]`. `fp` takes the raw `useMagicPoint_L1`, `useMagicPoint_L2`, `useMagicPoint_R1`, and `useMagicPoint_R2`; -1 is kept as is and MUST NOT be read as no cost. `group` is the key of the one `skillGroups` entry in [public/data/common.json](public/data/common.json) whose `sortGroupId` list holds the skill's `SwordArtsParam.sortGroupId` and, when the entry has a `defaultWepAttr` list, whose list also holds its `defaultWepAttr`. Each entry has `name` (`zh` and `en`). The groups follow the param sort groups, and their main sections match the Eldenpedia Nightreign skill list, which differs only in listing No Skill under shields and in having torch skills this site does not include: sort groups 10, 20, 30, and 120 (the base game's Heavy, Keen, Quality, and Occult Ashes of War, whose affinities Nightreign removed) form 無屬性 (a site name for Eldenpedia's No Affinity), and sort group 50 is split into 火焰 and 雷電 by `defaultWepAttr`. The other names come from the official affinity and weapon type wording and from the 專用戰技 caption heading; a group shows how the params sort skills, not a skill's damage type or usable weapons.
  - Spell costs, only for spells with a `Magic` row: `cost` from `mp` and `stamina`; `chargeCost` from `mp_charge` and `stamina_charge`, `null` when both are 0. They are raw params before any cost reduction. The page shows `chargeCost` as is and MUST NOT present it as whether a spell can be charged: a non-zero value does not show how charged casting works, a 0 does not mean no cost, and the two lines must not be added. The channeled cost `consumeLoopMP_forMenu` is not stored.
  - Icons: the script looks up `File:ER SB Icon <weapon|shield|Spell> <English name without colons>.png` on Eldenpedia (`shield` for the three shield types) and sets `icon: { "src", "page" }` only when the file exists and its page carries `{{License|game}}`; otherwise `icon: null`. Skills use the Nightreign icons `File:ERN Icon skill <English name without colons>.png` with the same license check. When several rows of the full `SwordArtsParam` share a `textId`, or one English name belongs to several `textId`s in the full `ArtsName`, whether or not those rows are included (for example 302 and 304 are both Parry), the name cannot tell which row an icon belongs to, so those skills get `icon: null`. Lookups are cached in `tools/.cache/eldenpedia/files.json`. Afterwards run `python tools/fetch-icons.py`, which downloads every referenced icon missing from `public/images/` and downscales it to 96px.
- The script stops without writing the data files when a weapon or spell name exists in only one language, a carried spell is not included, a named weapon has no default skill, a generation row references a missing skill pool, a pool entry with a weight above 0 has no skill, a referenced skill is missing from `SwordArtsParam` or has no English name or caption, a skill's English name matches more than one Ash of War, an Ash of War name lacks its prefix, a skill matches no skill group or more than one, `tools/skill-text-zh.json` is not the standard `JSON.stringify` output with 2-space indentation, lacks an included `textId`, has a key that is not one, or has an entry without exactly `cn` and `zh` each holding a non-blank `name` and `caption`, a `cn` text differs from the `erArtsCn` source, the English text of the two sources differs, a converted name differs from its Ash of War name, a spell-carrying weapon's `wepType` has no tag, a spell's `ezStateBehaviorType` has no tag, a weapon value or spell cost is not a number, a weapon references a missing `SpEffectParam` or `AttachEffectParam` row, a fixed effect has no name in both languages, two hit effects of a weapon give the same ailment, two icons share a file name, or a source it cites is missing from common.json.

## Character Data Generation

- `public/data/characters/nightfarers.json` is generated by [tools/import-characters.mjs](tools/import-characters.mjs) (`node tools/import-characters.mjs`, run from the repo root); it MUST NOT be edited by hand. It reads the pinned sources of [tools/relics-config.json](tools/relics-config.json) through [tools/sources.mjs](tools/sources.mjs), so characters come from the same game params as relics and armaments. Afterwards run `python tools/fetch-icons.py`, which also downloads the character icons.
  - Characters: `heroes` in the config maps each `characters` key of common.json to its `HeroParam` ID and `HeroMenuParam` ID, and the two key sets MUST be equal. `HeroMenuParam` has no character field, so its rows are mapped in ID order; every grade was compared with Eldenpedia to check this mapping.
  - Levels: the anchors are the `HeroStatusParam` rows that start at the character's `heroStatusParamId` with consecutive IDs, each at its `totalLevel`; their levels MUST rise from 1 to 15. A level without a row is the linear interpolation between the nearest anchors, rounded down. The params do not state this rule. It was checked against the level tables of the Eldenpedia Nightreign:Attributes page, and for the few differing cells, which include anchor rows, the site keeps its values from the params; pages MUST say that the levels between anchors are site calculations.
  - Caps: `maxHp`, `maxFp`, and `maxStamina` come from `vigor`, `mind`, and `endurance` through the `CalcCorrectGraph` rows 100, 101, and 104, linear between the five points `stageMaxVal` → `stageMaxGrowVal`. The params do not say which row the game uses; these rows were checked against the HP, FP, and stamina in the same Eldenpedia tables, and pages MUST say that the caps are site calculations. The script never rounds: it stops when a row is not linear (an `adjPt_maxGrowVal` is not 1), a stat is outside the row's range, or a result is not an integer.
  - Grades: `HeroMenuParam` `hpGrade`, `fpGrade`, `staminaGrade`, `strengthGrade`, `dexterityGrade`, `intelligenceGrade`, `faithGrade`, and `arcaneGrade`. The values 0 to 4 are S to D, checked against Eldenpedia for every character; any other value stops the script.
  - Text: no source with text IDs has the Nightreign character text, so [tools/character-text-zh.json](tools/character-text-zh.json) (keyed by character, then `passive`, `skill`, and `art`, each with `cn` and `zh` holding `name`, `summary`, and `description`) keeps in `cn` the official Simplified Chinese menu text exactly as on the BWIKI trilingual menu-text pages pinned by revision as `bwikiMenu` (a community copy of the game text, one page for the base game and one for the DLC). Each `cn` text MUST appear in the Simplified Chinese section of a page; when it appears on several lines, they MUST be on one page and share one English text. `en` is the line with the same line number in the English section, which has as many lines. The pages have no text IDs, so the curated `cn` text ties a text to its character; because the menu text is sorted by ID and the character text IDs rise with the `HeroParam` ID, the script checks that in each field the line numbers of the characters on one page rise with the `HeroParam` ID. `zh` is the site's Traditional Chinese conversion under the skill conversion rules (see Armament Data Generation), with 绝招 → 絕活 added as official Nightreign wording, so pages call it a site conversion. The menu text also renames Executor's skill to Suncatcher (攫阳), with its own summary and description; only the base name and text are included. Each ability records `sourcesFor` `["bwiki-menu-text"]` or `["bwiki-menu-text-dlc"]` by the page its text comes from.
  - Icons: `File:ERN Passive Ability Icon <name>.png`, `File:ERN Character Skill Icon <name>.png`, and `File:ERN Ultimate Art Icon <name>.png` on Eldenpedia, with the character's English name, under the same license check as armament icons.
  - Cooldown: `HeroParam` `characterAbilityCooldown`, stored as the skill's `cooldown`. Eldenpedia agrees for Ironeye, Duchess, Undertaker, and the three characters with no cooldown (0); Wylder (8 against 10) and Guardian (13.5 against 13) differ, so their `cooldownNote` cites the Eldenpedia value; Raider and Scholar have no community value. The use-count field is not stored.
  - Effects: [tools/character-effects.json](tools/character-effects.json) holds, per character, a non-empty list for `passive`, `skill`, and `art`, and an optional `cooldownNote`. An entry is either written from the params, `{ zh, checks, note? }`, stored with the sources `["game-params"]`, or a community mechanic summary, `{ zh, sources }`, citing the Eldenpedia character page pinned by revision (`eldenpedia-<character>` in common.json). A summary is used only where the params give no number for that mechanic, and MUST NOT repeat the official description. A community number MUST NOT appear in a param entry; it appears only in a summary or a `note`.
    - Each check reads one value: `{ ref }` reads `[table, id, field]` from `SpEffectParam`, `AtkParam_Pc`, or `Bullet`; `ratio` is `a ÷ b` rounded to 2 decimals; `sum` adds `terms`; `scale` multiplies `a` by `factor`. A field may be a group whose fields MUST all hold one value: `DamageCutRate*` (the eight damage types), `AttackRate*`, `AttackPowerRate*` (the five attack types), `AtkCorrection*` (the five `atk…Correction`), and `AilmentDefRate*` (the seven ailments). The value, rounded to `round` decimals when given, MUST equal `value`, and when the check has `display`, `zh` MUST contain that text; an entry needs at least one check with `display`, so the shown numbers are tied to the params.
    - Rows: the params have no row names, so the Smithbox row names (`smithbox-row-names`, commit c647be21, newer than the params) decide which row belongs to which ability. A row is used only when its name names the ability and one of these holds: a value in it or its reference chain matches Eldenpedia; a used row, or the ability's behavior (`BehaviorParam_PC` 6000000xx for skills and 7000000xx for arts, 50 IDs per character in `HeroParam` order), reaches it through param references; or, with no number to compare, the kind and direction of its effect match the official description or the Eldenpedia text (for example a damage cut for a stance that reduces incoming damage). Rows only next to a named row in ID, or whose name marks itself as uncertain, are not used.
    - Wording: field meanings follow the official Japanese descriptions in the base-game paramdef (`smithbox-er-paramdef`), in the wording of [tools/relic-details-params.json](tools/relic-details-params.json): `*AttackRate` is 傷害 ×, all five being 所有來源的傷害; `*AttackPowerRate` is 攻擊力 ×; `*DamageCutRate` is 受到的…傷害 ×, all eight being 受到的所有傷害; `toughnessDamageCutRate` is 受到的削韌; `*DefDamageRate` is 受到的異常累積; a negative `changeHpRate`, `changeMpPoint`, or `changeStaminaRate` is 恢復; `hitRadius` and `hitRadiusMax` are 半徑 and 最大半徑 in metres; the `AtkParam_Pc` corrections are multipliers on a base value, so they are shown only as ratios within one move and named 攻擊力補正 (`atk…Correction`), 削韌補正 (`atkSuperArmorCorrection`), and 精力削減補正 (`atkStamCorrection`), never as damage ratios, because the hits may also differ in attack type; `itemDropRate` × 100 is 觀察力, because Scholar's fowl-foot rows (0.3 and 0.4) match the 30% and 40% Eldenpedia records. Nightreign-only fields without an official description (`guardStaminaMult`, `changeGuardAngle`) are not shown. Damage values (`atkMag` and the like) are not shown, only ratios.
    - Verification: 26 values with the same quantity on the Eldenpedia pages were compared; 20 match. The 6 that differ keep the param value with a `note` or `cooldownNote`: Totem Stela raises all five attack types where Eldenpedia says physical, Tenacity's stamina recovery is 15 against +8 per second, Trance's damage taken is ×0.65 against 30% negation, Confluence's window is 4 against 3 seconds, and the two cooldowns above. A community record of a different quantity is not counted; it may still appear as a `note` (Necromancy's one-minute follow time against the ghost losing 2% max HP per second, and the enhanced Retaliate's +50% damage against its attack correction ratio of 1.69).
- The script stops without writing the data file when `heroes` and `characters` differ, a param table repeats an ID, a referenced param row is missing, a param value is not a number, a menu-text page lacks its Simplified Chinese or English section or the two have different line counts, the anchor levels are invalid, a grade is not 0 to 4, a `CalcCorrectGraph` row is not linear or gives a value out of range or not an integer, the text file differs from its canonical `JSON.stringify` output with 2-space indentation, has an entry without exactly `cn` and `zh` each holding a non-blank `name`, `summary`, and `description`, or has a key that is not a character, a `cn` text is missing from the pages or appears on several pages or with different English, the line order check fails, the texts of one ability come from different pages, or a cited source is missing from common.json; or when the effects file has a key that is not a character, a character without exactly `passive`, `skill`, `art`, and an optional `cooldownNote`, an empty list, an entry with unknown fields or that is neither shape, a `note` without exactly `zh` and non-empty `sources`, a check whose row or field is missing, whose group values differ, whose operation is unknown, whose value differs, or whose `display` is not in `zh`, or a param entry without a check with `display`.

## Game Writing Rules

- When linking to an external resource, open it in a new window; navigating away from the current page is forbidden.
- Follow responsive web design (RWD) principles and support phones, tablets, desktops, and other devices. No page, including its header, needs horizontal scrolling at any screen width of 280px or more, the width of the narrowest phones in use (the outer screen of a folding phone).
  - Tables: at a screen width of 900px or less, every table is shown row by row so that no table needs horizontal scrolling. Each row is a block whose first cell is its title; every other cell follows on its own line, with its column name in small text beside it. Wider screens and print keep the table. After the page is rendered, [public/render.js](public/render.js) copies each column header into the `data-label` of the cells in that column, except the first column, and sets the `table`, `rowgroup`, `row`, `columnheader`, and `cell` roles so the table keeps its semantics; the header row is hidden only visually. Every table MUST have one header row in `thead`, and every row MUST have as many cells as that header row; otherwise the page stops with an error.

    - When a new layout appears, first add a size rule for that position in `public/styles.css`.
    - The `width`/`height` attributes of `<img>` match the size for its position.
